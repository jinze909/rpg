# 002 · 亲手试出借声兽的规律

Status: Ready for implementation; blocked by story 001.

## 玩家得到什么

在入口安全区亲手摇铃、用湿布止声，看见借声兽按规则改变目标，并能回撤、重复试验。此卡只证明交互与反馈链可执行，不裁决整场救援是否好玩，也不决定移动／固定阵位胜负。

设计依据：[声井首个可玩样本](../../docs/gameplay/FIRST_PLAYABLE.md)与[玩法基线](../../docs/gameplay/BASELINE.md)。

## 范围

- 一张 PLACEHOLDER 场景，入口安全试验区；一名可控占位角色、一只兽、铜铃与湿布。
- 保存的真实玩家／场景配置、2D 输入与交互接线是必要前提；缺少时先补这条最短接线，不另造 RPG 状态系统。
- 声源只有清响／止声等明确状态，以命名位置处理；不做真实声波、完整潜行、战斗、第二伤员或整条 ST-04。
- 使用 ORK／Makinom 的单一权威事实，Unity 负责 2D 移动和可见反馈。具体 API 不可用时记录真实错误，不能用 Console 布尔演示替代玩家路径。

## 验收

| 检查 | 期望证据 |
| --- | --- |
| 实际进入场景并控制角色到达交互范围 | 同候选 Unity 导入／编译与 PlayMode 路径；输入、碰撞和对象引用有效 |
| 摇铃 → 兽朝声源转向或追索 → 包铃 → 兽失去该声源并进入可观察的搜索状态 | 实际画面或视频，以及目标状态断言；不能只有日志 |
| 清响与闷响有对应可视区别，必要信息不只依赖听力 | 观察目标变化、波纹／图标等占位反馈；PLACEHOLDER 标注齐全 |
| 可安全撤回、再次试验与重新加载 | 无重复对象、卡死或残留目标；引用、状态与资源恢复符合记录的起点 |
| 不向玩家直接讲完整答案也能察验线索 | 小范围观察并记录理解问题；未真人试玩则明确未验证，不宣称探索好玩 |

故事 001 的参数失败仍需先修复并取得真实运行证据。本卡尚无编译、运行或试玩结果。完成后下一项为加入三功能样本的短回合救援遭遇，不扩地图或系统规模。
