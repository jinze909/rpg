# 《归来》叙事事实登记表 v1.2

“归来”为工作标题。本表列出剧情需要“记住”的事实，供任务分解和后续实现参考。**它不是已实现的变量或 API，也不规定存储方式。** 事实名只是建议，实现侧可以改名、合并或拆分，但“记住什么、在哪里写入、在哪里被读到、缺失时怎么办”要保持一致。

职责沿用项目基线：ORK 管任务与存档，Makinom 管交互与剧情，Unity 管表现。具体落到哪一层，由玩法侧对照 gameplay baseline 判断。

## 二、写入与读取的原则

- 事实先记“发生过什么”，再记“怎么评价”。同一事实可以被多个章节读到，不同章节的反应可以不一样。
- 关键转折保留替代来源，证据各自有范围。缆口说明刀切；桥夫的目击和记事交代动手的是谁；陆钧自承交代命令及知情；韩峤署名的底稿说明官府怎样报了平安或战死，只据这份底稿无法指认断桥的人。
- 每个“被读到”的位置，都要有“缺失时”的默认值。默认值不能让人物说出和之前矛盾的话。
- 点名名单（roll_call_list）由事实生成，包括谁应声、谁没来、谁说“下次”。

## 三、软锁与一致性检查清单

- 沈砾、祁雀、韩峤、伊蕾、陆钧任何一位离队、翻脸或失去原有权限后，主线都有替代路线和更高的代价。
- 渡口之夜的证据丢失、被销毁或没拿到时，M12 仍能进行，只是你的牌更少。
- 战斗失败后的重试，与叙事选择造成的后果分开。重试不改变任何事实。
- 点名与名册是叙事要求，不是玩法承诺。如果玩法侧评估后不做名册对账，同样的叙事可以用对话与任务记录替代，M10 的拼写事件可以由伊蕾与矿工的对话完成。
- 没有暗中流逝的真实倒计时。重大转运、夺关、封航由章节事件推进，启程前说明会关闭哪些活动。
- 赤盐营救成功是共同节点。后续选择不追溯删除已经落脚的人。
- 终局区分 M13 的计划 `final_route_choice` 与 M14 的实际结果 `final_passage_outcome`；只有真实通路与接纳/退出条件成立才进入对应主结局。混合战术不等于改写主线选择，改线必须显式确认并重新检查阿鸢风险。M15/M16 对照真实去处与送达状态，不把镜湾安家的人自动放到临潮。
