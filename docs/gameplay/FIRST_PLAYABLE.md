# 《归来》首个可玩样本：声井救援

状态：完整救援代表环的设计已收敛，尚未完成、未试玩；002 声源机制链另有实现与自动化运行记录。本文落实[玩法基线 v0.1](BASELINE.md)，不改动其已定方向。下文的样本规模、角色功能、交互和节奏均为本次可撤销的工作默认，不是成品数值、队友名单或乐趣通过结论。

## 体验与内容定向

制作手工区域中的队伍叙事 RPG：玩家认识有自己打算的人，察验奇异现象，尝试办法，与伙伴合作，再看到行动怎样改变人和现场。战斗、交谈和探索各自可以有乐趣，也应在关键场景互相支持。内容深度优先来自可参与的处境、人物关系和真实回应；不以地图、技能或文本数量替代。

- 故事前台是具体冒险：闯进自己的纪念活动、救出困在声井的人、与刚救回的旧友共同脱困。名册、船贷、核验等保留为可信的条件与代价，不能连续占据玩家主要行动。
- 同伴通过共同做事建立关系，有本领、愿望、分歧和拒绝权。不要把所有人物都写成政策发言人或随身解题提示。允许幽默、虚荣、失误和胜利后的快乐，不用下一场灾难抵销每次成功。
- 探索以可读线索和亲手试验带来新办法，不靠全物件高亮和按顺序点提示。额外查看可以回报人物发现、近路或准备优势，不要求每个角落掉装备。
- 短回合围绕明确威胁与目标。玩家应能预判行动、分配保护和交互，而非每人轮流选择最高伤害。技能与装备的发展应带来新办法；首样本只保留少量功能，不预建完整成长树。
- 画面先用正交俯视、XY 平面和 PLACEHOLDER；成品画风仍开放。即使占位，也必须看清合法目标、怪物意图、铃声来源与结果。声音信息须有视觉对应，不以听力作为唯一解题条件。

## 剧情怎样落到可玩场面

主线、中段真正救回沈砾、后半共同冒险与成长均沿用[剧情基线](../narrative/STORY_OUTLINE.md)。不另起世界观。

叙事 v0.2 的正式开场先用 S00 白水渡序幕认识沈砾，再进入 M00“活人参加自己的英雄故事”：纪念活动中，小演员把主人公的战死演得错漏百出。玩家可以接话、匿名帮演、公开现身，或绕开演出找熟人；表达汇入既有韩峤会谈，不扩成多套独立章节。先产生行动和人物回应，再逐步交代战争背景，不把找身份证明做成长跑腿链。

S00 是叙事序幕，不是技术 P0；不改变本文声井样本先行的开发顺序。听雾的世界观关联也不要求本样本增加名册对账或航海系统。

祁雀仍在 M01 按现有大纲重逢，不将相认写两遍。她的调侃与一起处理眼前麻烦先建立相处感，再谈修船和事业。沈砾重逢场应先有共同动作、互相求助和真实胜利，随后再长谈；救回她不是故事结束。

地区故事各有自己的奇事、欲望和结局，不全部解释成同一阴谋，也不全变成营救资源清单。本文只试做 ST-04 的一次救援，不提前制作完整遗迹、运输道和地方结局。

## 本次完整样本的范围

目标体验约 10—15 分钟，仅作节奏预算，待试玩修订。第一张开发卡不要求一次完成整个样本。

| 项目 | 本次工作默认 |
| --- | --- |
| 场地 | 一张场景，入口安全试验区与声井内室两区；少量可辨认地标和一条撤回路线 |
| 人物 | 一名待救测路人；三名可控功能样本，不冻结正式同伴身份，也不自动把叙事 NPC 变成战斗队员 |
| 威胁 | 一只借声兽；追踪清亮铃声，攻击接近或阻路的活物，不新增模仿人声、读心等规则 |
| 器具 | 一只可转移铜铃、湿布、一扇闸门；入口铃位与侧廊铃位两个命名声源点，两种战斗版本完全一致 |
| 行动 | 普攻、保护、交互共用动词；角色专长只改变覆盖、距离或效率，不做三人对应三把锁 |
| 操作 | 沿用首轮三人、固定个人顺序；移动版有移动额度与一次主要行动，具体数值待调。未提交规划可取消 |
| 出口 | 测路人到达安全点即完成救援，不强迫清场；允许明确撤回入口 |
| 回应 | 一个救后人物场、一次目标成长结算和持久化恢复；不增加第二伤员、完整山镇回访或新支线 |

## 一段怎样玩

1. 入场先看到断铃绳、被拖空的骡车和钟绳边的爪痕，知道有人困在里面。不先听世界观讲义。
2. 在安全位置摇铃，看见兽朝声源转向；用湿布包住铃舌，看到清响与追踪状态改变。玩家能重复试验和回撤，同伴不提前讲完整答案。
3. 接近内室，测路人会阻止危险操作，并指出一段能承人的踏板。他想出去后亲手撤掉自己立错的路标，免得再带错人；这与救后动作闭合，不另加支线。他有判断和劳动，不是无反应的护送血条。允许一句真实的呼救，但怪物只模仿铃声，不混入新规则。
4. 玩家确认进入救援遭遇，观察下一次扑击区域，分配引兽、保护、开闸或攻击。危险由明确事件与回合推进，不在探索期间用隐藏真实倒计时害死人物。
5. 到达同一安全点后及时结束。测路人划掉自己画错的路线、收走危险路标，并针对玩家刚才的行动作回应。胜利有短暂喘息，不立刻追加一场灾难。

声源采用离散状态与命名位置，不模拟真实声波，不做音游、麦克风输入、通用潜行或物理沙盒。基础机制须可预测；画出的目标和实际结算一致，不能预告一处却偷偷攻击另一处。

## 必须兑现的两种计划

| 计划 | 玩家实际分工 | 可理解的代价与收益 |
| --- | --- | --- |
| 正面牵制／短战 | 一人保护或限制威胁，其他人攻击、开闸和接应 | 承担伤势与行动投入，换取移除眼前威胁或保留器具；攻击危险怪物是正当办法 |
| 铃声制造窗口 | 将兽引离救援线，其他人开路并掩护撤离 | 消耗主要行动和有限器具机会，选错声源会让兽堵住出口；不是免费无限控制 |

两种计划必须从同一保存起点独立完成，不靠调低某条路线的敌人强度或偷偷补资源制造可行。两者给同档目标成长，不能把引兽设成作者认可的唯一答案；也可混用，不强制固定操作顺序。若某条路同时更快、更安全、奖励更多，或每回合总是同一动作最优，应调整遭遇，而非加一排技能掩盖。

三名样本都能做基础动作；保护覆盖、远程牵引或器具操作效率可以有差别，不强制用某个特定人物开门。第一版不叠加 MP/AP/连携槽等多重资源；先用主要行动、现场器具和伤势形成取舍，具体范围、次数、耐久、伤害与回合数均待实测。

重试恢复已记录的遭遇前资源、位置、声源和任务状态，跳过已听长对白。样本失败不自动写成永久人物死亡。任务、奖励、战斗和存档用 ORK 同一份权威状态，Makinom 组织交互，Unity 负责表现；不另建一套演示 RPG 状态。

## 移动与固定阵位的裁决

完整移动版后制作对照版，保持目标、威胁、两处声源、主要行动预算、角色功能、剧情结果和教学质量相同。固定版保留引铃、保护／阻断、交互和撤离推进，不削成轮流普攻。暂时无法等价的机制不用于证明移动优劣。

若理解规则后，移动仍主要增加追近、选格与等待，优先投入固定阵位；若位置持续改变保护、诱导和撤离顺序，且负担可接受，继续移动版。这里只裁决该遭遇的下一步投入，不宣称整作战斗已经定型。

## 试玩看什么

先排除输入、提示与执行错误，再观察人物、探索、战斗和疲劳。不要给出正确解法；记录主动试验、追问、改变计划和无效操作。安全节点可问“你预计会发生什么”，不每回合打断。

- 玩家能否依据观察自行提出并试验一种办法，而非只跟高亮按钮。
- 玩家是否记得测路人的愿望或主动行为，是否在意救后回应，而非只看任务勾选。
- 普攻、保护和交互是否各有合理用途，局面变化时是否改变分工。
- 结束后是否自愿想试另一办法、继续认识人物，以及具体原因；一句“挺好玩”不单独作为通过。

两版交叉试玩顺序。人物吸引力只用首次接触那版观察，不能把第二次已知故事的冷淡当作叙事失败。不设虚构行业标准或固定人数通过线。

最强失败反例：玩家不理解兽的规律，也不关心测路人，只按高亮顺序就无伤完成并拿满奖励。即使通关测试全绿，体验仍不通过。另一反例是理解之后只剩固定“摇铃—开闸”答案。

## 开发入口与范围上限

技术与声源试验已有[001](../../production/stories/001-ork-bootstrap.md)、[002](../../production/stories/002-soundwell-signal.md)记录的同 SHA 自动化验收；保留对应候选和 run 的证据边界，不把旧的 GameCI 参数失败当作当前阻塞。叙事 v0.2 没有重新验证或改动这些实现。

[002 声源试验](../../production/stories/002-soundwell-signal.md)已实现单角色摇铃、包铃、兽响应与回撤链，并取得自动化证据。下一项是 [003 · 三人短回合声井救援](../../production/stories/003-soundwell-turn-rescue.md)的移动版。002 的真人试玩独立保留。固定阵位对照、救援／结算／持久化闭环和乐趣验证仍是完整样本的验收项。

本样本不做职业树、大装备经济、制作采集、世界地图、多怪物种类、正式配音、成品美术、专用小游戏或完整地方线。必要的反馈和教学属于样本本体，不能为缩范围全部删掉。
