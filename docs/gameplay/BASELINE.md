# 《归来》一页玩法基线 v0.1

状态：设计基线，声井部分链路已有实现；实际进度见[故事003](../../production/stories/003-soundwell-turn-rescue.md)，主观乐趣尚无实证。配合[剧情大纲](../narrative/STORY_OUTLINE.md)使用。**已定**是当前产品方向；**暂定**仅约束指定原型，可撤销；**待验证**须记录运行证据及适用条件，经设计评审再更新状态。好玩第一，文本、功能数与通关均不等于体验通过。

本轮已收敛的[首个可玩样本](FIRST_PLAYABLE.md)明确声井救援的范围、两种计划、人物回应、对照方法及首张开发卡。它补充原型工作默认，不把未试玩假设升级为成品结论。

剧情现采用[叙事 v0.2](../narrative/STORY_OUTLINE.md)。点名与受限听雾是写作基线；专用名册界面、对账判定和航行听雾操作仍待单独验证，不由叙事稿自动扩充本页的玩法或首样本范围。

## 已定：玩家体验与边界

- **定位与循环：**2D单机队伍叙事RPG。在手工区域自由探索，认识人物、观察情况，选择并尝试办法，与伙伴行动，得到人物/场景回应，再培养队伍或继续冒险。主线中段重逢、后半共同成长，地区故事独立成立。
- **参与：**观察与试验、交谈与交涉、使用物品/机关、引导与接应，按场景需要复用。线索可推断，已知代价可理解，行动能改变现场或关系。交谈、幽默、表达和相处可独立提供乐趣；不要求每场加谜题或每个任务三解。关键目标要有可继续的办法，失败可带来新处境与代价。
- **伙伴：**有自己的愿望、提议与拒绝权，专长实际改变分工、准备或风险；叙事盟友不自动成为战斗队员。已设计的合理退出不能锁死主线，替代可花钱、耗资源或更危险，不承诺全员能力等价、随时缺席皆无影响。
- **成长与反馈：**技能、装备和合作须带来新办法。有效完成目标不因未杀敌而自动少一档成长，同一成果不能重复领奖；地方故事也可回报信息、关系或生活变化。反馈可以是行动、称谓、笑声、争执和回访变化，不能只看任务勾选或好感数。
- **节奏与后果：**队伍短回合为战斗骨架，遭遇围绕明确威胁和目标；目标达成/投降后由规则及时结算。重大章节截止须预告并由玩家确认，不用隐藏真实倒计时惩罚探索；操作失败重试与叙事选择后果分开。

## 已定：严格像素风与 AI 美术资产规格（M8）

正式作品采用 **严格像素风**。世界 Sprite/Tilemap 统一 **16 Pixels Per Unit**，逻辑参考分辨率 **320×180（16:9）**。新制像素素材必须使用整数网格、Point（Nearest）过滤、关闭 mipmap/有损压缩，角色与地图单位尺度需一致，Pivot 对齐源像素网格。唯一的 URP 2D Pixel Perfect Camera 与 Cinemachine 3 Pixel Perfect 扩展管理实际镜头；相机视觉跟随在 1/16 世界单位网格上取整，不改变 ORK 物理/战斗位置。无法完整整数缩放时使用必要的黑边，不为铺满屏幕强行非整数拉伸。UGUI 仍为高分辨率 Screen Space Overlay，以保证文字与点击区域的可读性。

严格像素约束让 AI 生成的资产在像素尺寸、锚点与跨帧比例上更易自动验收，但**不会自动保证动画连贯**。当前已有的矢量线条、世界空间文字和临时形状只是原型占位，M8 不把它们冒充已完成的像素美术；它们应在后续故事阶段逐步替换。宽屏、方形、竖屏实际 Unity 截图和 CI 验收仍是 M8 必须的工程证据。

## 暂定：仅首轮原型的控制条件

| 项目 | 工作默认与边界 |
| --- | --- |
| 呈现与操作 | PC键鼠主测，正交俯视、XY平面占位场景；关键操作按导航/确认/取消设计，必要信息不只靠悬停。选型前抽查手柄核心流程；G1完整键鼠/手柄焦点与分辨率验收仍保留，成品严格像素风与 16 PPU 已定；其他占位视觉待逐步替换。 |
| 队伍与回合 | 三名可操作角色，固定个人行动顺序；移动版用移动额度＋一次主要行动，固定阵位版给同功能的保护/阻断等行动。两版主要行动预算与威胁一致，先隔离移动变量；人数、预算与自由排序仍可另验。 |
| 信息与重试 | 显示行动者、合法目标/范围、消耗及已知风险；概率、结果区间、明确未知均可，不能假预告。未提交规划可取消且不扣资源；确认后由ORK执行并按规则扣费，不承诺已提交行动回滚。原型验证恢复已记录的战前资源、目标与敌人初始状态，跳过已听长对白；战中存档未定。 |
| 能力样本 | 用少量有区别的技能、装备与场景对象验证配合；预览不可信先缩小集合。能力检定与随机失败暂不承担唯一通关条件；职业树、装备经济及普遍可学能力尚未定型。 |

## 待验证：一段完整体验，两个公平版本

代表环采用钟岭声井救援：察验铃声规律、接触有愿望的测路人，准备并行动，引兽/开闸/保护撤离，随后获得人物回应。对照移动版与固定阵位版：相同目标、威胁、队伍功能、行动顺序与剧情后果，两版都补齐教学、预览、取消、重试；记录智能体测试顺序与输入条件，不拿简陋版对比精修版；不要求用户试玩或反馈。

- **理解与主动参与：**玩家是否据线索自行尝试、追问人物或改变计划；只会复述目标、追高亮和领取奖励不算乐趣成立。对人物、探索、战斗分别观察，不用战术效率代替所有吸引力。
- **移动的价值：**能否说清两种可行办法及不同代价，位置是否持续改变救援顺序、分工或风险。若主要多了追近、选格与等待，优先固定阵位；若增加值得思考的取舍且负担可接受，再继续投入移动版。
- **裁决边界：**由智能体记录实际操作、反馈、可读性和重复负担；真实玩家的疲劳、兴趣和继续意愿无证据时保留未知，不用AI推测代替实测。先排除信息、执行和教学问题，再以可用证据作可逆设计判断；不设用户参与门槛，缺口写入[问题记录](../../production/KNOWN_ISSUES.md)。单场与固定顺序的结果只决定下一轮投入，不证明整作成立。

**后续执行：**原型是可撤销试验，不限制正式作品的内容目标。Unity 6000.6.8f1／ORK 3.22.0／Makinom 2.21.0先通过[启动验收](../../production/stories/001-ork-bootstrap.md)；源码有能力不等于运行通过。ORK统管战斗、成长、任务与存档，Makinom组织交互演出，Unity负责2D表现与输入，同一事实不重复保存。

任务可以补充可逆、不改变对照条件的局部默认并注明理由；不得默默升级暂定或待验证项。核心体验或比较口径的空白先回设计层讨论，更改既有冻结方向按[工作室流程](../../production/workflow.md)处理；未经授权不扩大到完整潜行/物理沙盒、专用小游戏或大规模内容生产。主角自定义范围、外观、恋爱系统与最终时长仍开放。
