# 《归来》500 倍大世界地图扩张、地标任务与 ORK/Makinom 底层整合总规划

## 1. 背景与核心目标

当前 `codex/dev` 上的四张可探索地图仍停留在早期 4x 样板体量（单张 80×44 至 140×84 格，玩家步行约 10 秒即可横穿全图），缺少完整 RPG 的空间纵深、区域探索节奏、支线地标循环与长程导航体验。

本规划确立本阶段的首要开发目标：在不推倒现有工程、不破坏主线叙事与 Unity P0 CI 稳定性的前提下，**将全部四张主探索地图扩张至约 500 倍面积**，围绕《归来》世界观补齐完整的**地标标记、地标探索任务、快速传送灯标、休整营地与高危遭遇战区**，并深度整合仓库现有的 **ORK Framework 3、Makinom 变量持久化、16-PPU 分块渲染器与小地图导航系统**。

## 3. 地标分类体系与探索循环设计

### 3.1 六类标准化地点标记（`RpgMapMarkerCategory`）
每张地图均按以下 6 类标记统一分层，兼顾主线推进、自由探索、风险回报与大地图机动：
1. **主线关键点（`MainStory`）**：锚定原有主线触发点与剧情节点（如声井铜铃/湿布/撤退井口、外港登岸岗/瑟兰代书摊/修船摊/盐市/矿营入口、白水渡主缆锚/桥头防线/东岸阵地、矿营账房/提升机/主泵房）。
2. **地标任务点（`LandmarkQuest`）**：承担区域环境叙事与独立探索任务（勘察、机关检修、补给回收、测绘、清障、声学验证）。
3. **快速传送灯标（`FastTravelBeacon`）**：每图分布 5–6 座，覆盖核心主干与远端分区；**必须由玩家实际抵达并发现后才解锁传送**，解决 500 倍大地图折返耗时过长的问题。
4. **补给休整营地（`CampAndSupply`）**：避险石室、缆绳库、伤病棚、辎重车阵、蒸汽伙房与下层避难洞，联动 ORK 队伍恢复与物资补给。
5. **档案线索点（`LoreArchive`）**：壁龛刻痕、税关货册、旧盐秤公房、旧渡口水文簿、水压表读数室等，提供与《归来》主线/支线呼应的可核实世界观证据。
6. **高危警戒区（`DangerZone`）**：沉降排水渠、积水闸门间、深层回声溶洞、西货场巡逻区、北沙洲浅滩、东桥段拒马阵、护矿队营房与下层排水闸门，绑定巡逻警戒与 ORK 遭遇战。

### 3.2 六类地标探索任务（`RpgLandmarkQuestKind`）
- `InspectClue`（实地勘察/核对账册与机关）
- `ActivateBeacon`（点亮风灯/火盆/雾角/制动校验）
- `SalvageSupply`（回收滑轮、麻丝、灯油、扳手、伤药等物资）
- `ClearHazard`（疏通排水栅、泄压、清障、拆拒马、清浮木）
- `SurveyRoute`（测绘安全航线、照明盲区、换岗窗口与撤离路线）
- `WitnessEcho`（声井回声对比、防波堤听风声、矿营换班钟声计时）

### 3.3 四张地图的分区与地标骨架
- **声井地下群（`Soundwell`，2,144×1,344）**：围绕下井主入口、北侧回声长廊、中央钟岭主井厅、东侧铜铃与湿布室、西侧铁闸暗廊、南侧撤退井口 6 大宏区扩展多条 6–8 格宽主巷道与 4 格宽支线密道，布局 18 处标记与 15 项任务；保留铁闸未开前物理阻断撤退井口的核心谜题约束。
- **赤盐外港大港区（`RedSaltHarbor`，3,136×1,888）**：南临深水/浅滩海面与防波堤，中段展开浅水泊位、石码头长堤、修船摊与干船坞滑道、赤盐盐市与晒盐灶台、西货场栈棚，北接石门坊与矿营入山口，布局 20 处标记与 16 项任务，串联全部 M05 触发点与 M06 入口。
- **白水渡跨江战区（`WhitewaterCrossing`，1,792×992）**：西岸前线营地与辎重车阵、旧摆渡石埠、北沙洲浅滩，中段跨越超长浮桥（西桥头防线、江心浮筏中段、东桥段拒马阵），东岸延伸至残断旧桥墩、观江哨塔、补给棚与撤离山口，布局 16 处标记与 13 项任务。
- **赤盐矿营与地下泵房（`MineCamp`，2,144×1,440）**：南门与检疫岗、护矿队营房与巡逻哨楼、物资账房/盐煤堆场/铁匠棚、换班通道/矿工宿舍/蒸汽伙房/矿车转盘、上层疏散道与提升机控制室、地下主泵房与水压表读数室/下层避难洞，布局 18 处标记与 16 项任务。

## 4. 底层技术栈深度整合架构

### 4.1 视野流式分块渲染器（`RpgLargeMapChunkRenderer` Streaming）
- **核心痛点**：原渲染器启动时为整张图每一个 32×32 chunk 一次性创建 `512×512 RGBA32` 贴图（每块 1 MB）。在 500 倍面积（最高 5,782 chunks）下会直接申请近 6 GB 显存导致 OOM 与 CI 超时。
- **改造方案**：
  - 保留原有小图构建重载以兼容既有测试；新增流式构造入口 `BuildStreaming(...)` 与每帧/位移驱动的 `UpdateFocus(Vector2 centerTile, int activeRadiusChunks = 3)`。
  - 仅实例化围绕当前镜头/玩家坐标的 `(2R+1)×(2R+1)` 窗口内 chunk（`R=3` 时最多 **49 个活跃 chunk**，显存占用恒定 `< 50 MB`），超出窗口的 chunk 立即卸载并安全销毁 `Sprite` 与 `Texture2D`。
  - 复用现有 `RpgPixelArtManifest` 16-PPU Point 过滤切片缓存，一次提取切片后供所有流式 chunk 共享；光源光晕（`RpgLight2DAnchor`）同样按视野裁剪启用/隐藏。

### 4.2 紧凑低内存地图数据与快速连通性校验
- **内存优化**：500 倍地图地块阵列采用 `byte[,]` 或分块稀疏/宏区划采样器（最大图 `3136×1888` 仅占 **5.9 MB**），避免 4 字节枚举数组与 GC 抖动。
- **大世界地形生成与手绘锚点结合**：采用确定性宏区划模板 + 主干道/环线/支线走廊雕刻 + 72 个地标广场与周边安全缓冲圈，确保每个地标、主线触发点、传送落点与巡逻航点均落在可行走地块上。
- **CI 友好校验**：对 500 倍图采用**宏区划图连通性校验 + 走廊断面校验 + 局部地标可达性采样**，既严格证明全图无死锁/断路，又将单测耗时控制在毫秒级。

### 4.3 ORK Framework 3 深度整合（战斗、队伍、营地与奖励）
依托仓库已集成的 ORK 桥接层（`OrkPartyBridge`、`SoundwellOrkParty`、`OrkRoleEncounter`、`OrkCombatLockBreakAdapter`、`CombatLockBreakRules`、`BattleFeelAndTelegraphDirector`、`PartyFormationFollower`）：
- **大世界探索编队**：玩家在大地图移动时通过 `PartyFormationFollower` 维持完整小队编队与碰撞安全跟随，支持常规步行与疾跑（Sprint）两档速度。
- **营地休整（`CampAndSupply`）**：玩家抵达已发现营地地标并交互时，通过 `OrkPartyBridge` / `SoundwellOrkParty` 执行队伍状态恢复（生命/专注/异常清理），并记录营地补给状态。
- **高危区巡逻与 ORK 破锁遭遇战（`DangerZone`）**：将大地图高危区及 `BeastPatrolAndChase` / `SoundwellBeastPatrolTracker` 巡逻群接入 `OrkRoleEncounter` 与 `OrkCombatLockBreakAdapter`，支持警戒侦测、切入破锁战术战斗、胜利后推进对应 `ClearHazard` 地标任务并解除局部警戒。
- **地标任务奖励闭环**：完成 `RpgMapExplorationTracker` 中的地标任务后，通过桥接回调发放 ORK 物品/补给/经验/线索标记，并同步更新 `ReturnStoryLedger`。

### 4.4 Makinom 变量持久化与状态隔离
- 所有地标发现状态与地标任务进度统一通过 `Maki.Game.Variables`（经由可测试的 `Func<string, int>` / `Action<string, int>` 委托）持久化：
  - 地标发现键：`rpg.return.world.marker.<markerId>`（`0` 未发现 / `1` 已发现）
  - 任务进度键：`rpg.return.world.quest.<questId>`（`0..RequiredSteps`）
- 严格遵守仓库防撕裂与单向推进约定：绝不污染或覆盖现有 `M00..M16`、`ST01..ST06`、`RC01..RC05` 的主线/支线键值，并在显式新周目重置时统一清零。

### 4.5 降采样小地图、世界总览与罗盘 HUD（`RpgLargeMapMinimapAndBeaconHud`）
- **固定分辨率降采样**：小地图纹理固定为紧凑分辨率（如 `192×120` 或 `224×128`），按采样步长映射 500 倍大地图地形，彻底杜绝按原图 1:1 尺寸创建数千像素贴图。
- **分类图钉与发现迷雾**：仅高亮已发现地标、当前追踪任务目标与解锁传送灯标；高危区巡逻威胁图标继续实时同步。
- **罗盘与快捷传送面板**：HUD 显示当前所在分区名、追踪地标任务名、进度（如 `1/2`）、八方位中文方向与剩余格距，并允许玩家从已发现的 `FastTravelBeacon` 列表中选择安全传送。

## 6. 性能、安全与 CI 验收红线

1. **显存与活跃区块红线**：流式模式下单图活跃 chunk 数严格受限于 `(2R+1)^2`（默认 `R=3`，上限 49 块），`Dispose()` 必须 100% 释放所有运行时 `Texture2D` 与 `Sprite`。
2. **数值安全红线**：所有坐标、位移、距离、方向与传送入口均拒绝 `NaN` / `Infinity`（使用 `!float.IsNaN(v) && !float.IsInfinity(v)`，不使用 `float.IsFinite`）。
3. **测试与元数据规范**：所有新增 NUnit 测试仅使用 `[Test]`（不使用 `[TestCase]`）；`Assets/` 下所有新增 `.meta` 文件均带唯一 32 位十六进制 GUID 且以换行符结尾。
4. **严格隔离原则**：所有扩张增量均在自有 `codex/pending/world-500x-*` 分支逐项提交、验证同 SHA `evidence` + `bootstrap` 双绿后合入 `codex/dev`，不触碰任何外部候选分支。
